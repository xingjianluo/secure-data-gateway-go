# 本地数据访问网关（Go）

用本地内存存储模拟主体目录、数据源、策略与审计记录，实现一条统一的
**授权判定 → 字段脱敏 → 审计留痕** 管道。无论请求从哪个入口进入
（按资源 ID 取数 / 调用方自带数据），结论都一致、确定、可复现。

无任何外部依赖，仅使用 Go 标准库。

## 目录结构

| 文件 | 职责 |

## 授权规则

判定输入为 **主体属性（部门、角色、敏感级别上限 clearance）+ 资源敏感级别 + 操作类型**。

1. **主体识别**：主体 ID 在目录中不存在 → 直接拒绝，原因 `unknown_subject`，
   对应错误 `ErrUnknownSubject`。
2. **资源存在性**（入口一：按资源 ID 取数）：资源不存在 → 拒绝
   `resource_not_found`，对应错误 `ErrResourceMissing`。该归属与策略无关，
   对账时不会混入策略责任。
3. **策略匹配**（每条规则为白名单语义，空列表表示通配）：
   - 系统里根本没有可用策略（未加载或策略无规则）→ 拒绝 `policy_not_found`；
   - 策略存在，但规则的 `departments` / `roles` 均不容纳该主体
     → 拒绝 `no_matching_rule`（与 `policy_not_found` 严格区分：
     前者责任在"规则未覆盖该主体"，后者责任在"系统无可用策略"）；
   - 有候选规则但均不允许本次 `action`（`read` / `write` / `delete`）
     → 拒绝 `action_denied`。
4. **级别判定**：允许该操作的规则中，取 `max(资源级别, 规则 min_level)`
   作为所需级别；主体 `clearance` 不足 → 拒绝 `level_insufficient`，
   审计依据中同时记录所需级别与主体级别。
5. 以上全部通过才放行。

全部拒绝归属 **两两互异**（见 `DenyReason` 常量），
对外错误也可通过 `errors.Is` 区分
（`ErrUnknownSubject` / `ErrResourceMissing` / `ErrAccessDenied`），
不存在静默放行或统一归类。

每次判定都记录依据：策略版本、命中规则 ID 与描述、参与判定的规则列表、
所需/持有级别，写入审计并在日志中打印。

## 脱敏规则

字段带有敏感级别（`public=0 < internal=1 < confidential=2 < secret=3`）。
放行后按策略 `field_modes: {级别: {操作: 模式}}` 逐字段处理：

| 模式 | 行为 |
| --- | --- |
| `keep` | 原样返回（缺省值） |
| `mask` | 部分遮蔽，保留首尾可读（如 `13812345678 → 1****8`） |
| `tokenize` | 不可逆令牌：`tok_` + `HMAC-SHA256(secret, "v1"·字段名·规范值)` |
| `drop` | 整体剔除 |

此外，**字段级别高于主体 clearance 时无论策略如何配置都整体剔除**：
输出 map 中不存在该键，不会返回空值、零值或占位符。

一致性与安全性：

- 令牌化是无状态纯函数，并与**字段名**绑定（避免不同字段同值被关联推断）；
- 同一主体重复访问、多协程并发访问，输出逐字节一致（测试用 `-race` 校验）；
- 令牌不含明文片段，无密钥不可逆；进程/状态重载后只要密钥不变，令牌不变；
- 换密钥则令牌不同，密钥不参与任何返回值外泄。

## 策略版本与热更新兼容范围

- 策略以 `*Policy` 整体发布，**发布时深拷贝、发布后不可变**（调用方事后修改
  原指针不会污染已发布版本）；`Store` 用原子指针保存当前版本，
  判定开始时取一次快照，**进行中的判定永远基于同一个完整版本，读不到半更新状态**。
- 版本号采用 `major.minor.patch`（缺段补 0）。
- 加载新版本时按顺序校验，任一失败都返回错误且 **原策略继续可用，不部分生效**：
  1. 合法性：版本非空、至少一条规则、规则 ID 非空、枚举合法；
  2. 不允许版本回退（`next < current` 返回 `ErrIncompatiblePolicy`）；
  3. 兼容性下界：新版本声明的 `min_supported` 不得高于当前版本，
     即 `current >= next.min_supported` 才接受。
- JSON 文件中 `min_supported`、`field_modes`、`description` 等字段缺失
  视为旧版定义，按缺省容忍加载；非法枚举（未知 action / mode）明确报错。
- 判定结论中带有所用策略版本；保存旧策略快照即可在任意时刻用判定引擎
  **复现旧版本上的历史结论**，不受当前新版本影响（有对应单测）。

策略文件示例见 `gateway/testdata/policy-v2.json`：

```json
{
  "version": "2.0.0",
  "min_supported": "1.0.0",
  "rules": [
    {"id": "legal-read", "departments": ["legal"], "actions": ["read"], "min_level": 1}
  ],
  "field_modes": {"2": {"read": "tokenize"}}
}
```

## 历史版本保留与淘汰

`Store` 在热更新之外保留一段有限的历史版本，供事后按版本复现：

- 每次 `Update` 成功后，被替换下来的版本**深拷贝**进入历史（由旧到新有序），
  入列后只读，任何后续操作都不会再改动它；
- 保留上限可配置：`NewStoreWithRetention(initial, n)`（默认
  `DefaultHistoryRetention = 8`，不含当前在用版本；`n <= 0` 表示不保留历史），
  运行中也可用 `Store.SetRetention(n)` 调整——调低时立即按由旧到新淘汰，
  同样只摘索引、不影响已发出的快照；
- 历史超出上限时**按由旧到新淘汰**；**当前在用版本永远不会被淘汰**；
- 淘汰只从索引中摘除条目，已发出的快照指针依然完整有效——
  **淘汰与保留上限调整都不会打断正在进行的访问判定与复现**；
- 被淘汰的版本号会留痕（有界队列），查询反馈严格三分：
  - 当前版本 / 保留期内的历史版本 → `Store.Version(v)` 返回只读快照；
  - 曾经发布但已被淘汰 → `ErrVersionEvicted`（**绝不拿当前最新版本顶包，
    也不当作不存在**）；
  - 从未发布过 → `ErrVersionNotFound`（与淘汰明确区分）。
- `Store.Versions()` 返回当前可复现的全部版本号（历史由旧到新，当前版本在最后）。

## 历史复现与对账

每条审计记录都带有判定时的**主体属性快照**与请求原文，因此复现的判定输入
完全来自记录本身，不依赖主体目录的当前状态。

- `Gateway.Replay(rec, version)`：用指定版本（空串表示记录当时生效的版本）
  重新判定，并与原始记录**逐项对账**——是否放行、拒绝归属、命中规则 ID、
  判定依据、策略版本（评估时间戳除外）。版本已淘汰/不存在时直接返回
  `ErrVersionEvicted` / `ErrVersionNotFound`，不产出任何结论。
- `Gateway.ReplayBatch(recs, version)`：对一批（或 `Logger.RecordsInWindow`
  筛出的一段时间窗内）已记录访问批量复现。结果顺序与输入一致；判定是纯函数，
  **同一批输入反复执行，输出内容与顺序必然稳定**，且与逐条复现完全一致。
  某一条版本不可复现时，该条位置填入明确错误项，不影响其余记录对账。
- **复现是纯函数**：不写审计、不改动任何可观察状态。复核前后审计条数、
  记录内容、时间窗查询结果完全一致——复核本身不会污染后续对账的输入，
  同一批复核请求反复跑，结果必然相同。
- 复现与两条访问入口（按资源取数 / 调用方自带数据）**共用同一套判定引擎
  与判定口径**：同一版本同一输入，从任何入口、正常访问或按版本复核，
  得到的归属与结论一致。
- 复核结果中拒绝归属保持六类可区分、互不混淆：
  - `unknown_subject`：主体目录查无此人（与策略无关）；
  - `resource_not_found`：被访问的资源本身不存在（与策略无关，
    不混入任何策略类归属）；
  - `policy_not_found`：当时系统里根本没有可用策略；
  - `no_matching_rule`：策略存在，但当时没有任何规则覆盖该主体；
  - `action_denied`：有规则覆盖主体，但操作类型不被允许；
  - `level_insufficient`：操作被允许，但主体敏感级别不足。

本地命令行复查（无需改代码）：

```bash
# 1) 运行演示，结束时自动导出 audit-demo.json
go run ./cmd/demo

# 2) 加载历史版本沿革 + 审计导出，按各记录当时生效的版本复现对账
go run ./cmd/replay -audit audit-demo.json \
  -policies gateway/testdata/policy-v1.json,gateway/testdata/policy-v2.json

# 可选：-version 2.0.0 统一指定复现版本（跨版本差异会被逐项列出）；
#       -seq 3 只复查某一条记录。全部一致退出码 0，否则为 1。
```

## 本地验证

```bash
# 全部单元测试（含输入与判定依据日志）
go test -v ./...

# 竞态检测（覆盖重复/并发脱敏一致性、并发热更新不读半状态）
go test -race ./...

# 静态检查
go vet ./...

# 端到端演示：正常访问、三类拒绝、未知主体、热更新与兼容拒绝、审计打印
go run ./cmd/demo

# 本地复查：按记录当时生效的版本复现对账（demo 结束后会提示完整命令）
go run ./cmd/replay -audit audit-demo.json \
  -policies gateway/testdata/policy-v1.json,gateway/testdata/policy-v2.json
```

测试覆盖场景：

- 越权（操作被拒 / 级别不足）、未知主体、无规则覆盖、系统无策略、资源不存在，
  六类拒绝归属两两可区分（含资源不存在不混入策略类归属）；
- 脱敏与令牌化在重复访问、50 协程并发访问、脱敏器状态重载下结果一致；
- 无权字段整体剔除（无键、无空值、无占位符）；两个入口输出一致；
- 并发热更新期间判定快照自洽；兼容版本接受、不兼容/降级/非法版本拒绝且原策略可用；
- 已发布版本不可变：调用方事后修改原策略指针不污染快照；
- 旧版本历史判定结论可复现；审计记录包含输入、判定依据、保留/剔除字段，
  测试日志中打印输入与依据（`go test -v` 可见）；
- 按版本复现与原始结论逐项一致（含热更新后用旧版本复现、跨版本差异逐项列出）；
- 批量复现与逐条复现一致，同一批输入反复执行输出内容与顺序稳定；
- 复现为纯函数：反复复核后审计条数、记录内容、时间窗查询结果不变，
  复核不影响后续对账；
- 版本淘汰后复现返回 `ErrVersionEvicted`（与 `ErrVersionNotFound` 可区分，
  不拿当前版本顶包）；当前版本在 retention=0 时也不可被淘汰；
- 保留上限运行中调整（`SetRetention`）：立即淘汰、明确反馈，
  已持有快照的进行中复核不受打断；
- 并发更新（触发淘汰）与并发复现叠加时结果自洽（`-race` 校验）；
- 复现结果中六类拒绝归属（未知主体 / 资源不存在 / 无可用策略 /
  无规则覆盖 / 操作被拒 / 级别不足）可区分；
- 按时间窗筛选记录并批量复现对账。
