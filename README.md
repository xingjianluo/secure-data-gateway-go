# 本地数据访问网关（Go）

用本地内存存储模拟主体目录、数据源、策略与审计记录，实现一条统一的
**授权判定 → 字段脱敏 → 审计留痕** 管道。无论请求从哪个入口进入
（按资源 ID 取数 / 调用方自带数据），结论都一致、确定、可复现。

无任何外部依赖，仅使用 Go 标准库。

## 目录结构

| 文件 | 职责 |
| --- | --- |
| `gateway/model.go` | 主体、资源、请求、判定、规则、策略、审计记录等类型定义 |
| `gateway/subjects.go` | 内存主体目录（模拟主体属性数据源） |
| `gateway/policy.go` | 无状态授权判定引擎：ABAC 匹配 + 区分拒绝原因 + 记录依据 |
| `gateway/masking.go` | 字段级投影：保留 / 脱敏 / 不可逆令牌化 / 整体剔除 |
| `gateway/store.go` | 策略存储：原子快照、安全热更新、版本兼容校验 |
| `gateway/policyfile.go` | 本地 JSON 策略文件加载（旧版字段缺失可容忍） |
| `gateway/audit.go` | 审计记录器：内存留存 + 实时打印输入与判定依据 |
| `gateway/datasource.go` | 内存数据源（读写均做深拷贝） |
| `gateway/gateway.go` | 网关组装与两个统一入口、`ReloadPolicy` |
| `cmd/demo/main.go` | 可运行的端到端演示 |
| `gateway/testdata/` | 热更新测试用策略 JSON |

## 授权规则

判定输入为 **主体属性（部门、角色、敏感级别上限 clearance）+ 资源敏感级别 + 操作类型**。

1. **主体识别**：主体 ID 在目录中不存在 → 直接拒绝，原因 `unknown_subject`，
   对应错误 `ErrUnknownSubject`。
2. **策略匹配**（每条规则为白名单语义，空列表表示通配）：
   - 规则的 `departments` / `roles` 容纳该主体才算候选规则；
   - 没有任何候选规则 → 拒绝 `policy_not_found`；
   - 有候选规则但均不允许本次 `action`（`read` / `write` / `delete`）
     → 拒绝 `action_denied`。
3. **级别判定**：允许该操作的规则中，取 `max(资源级别, 规则 min_level)`
   作为所需级别；主体 `clearance` 不足 → 拒绝 `level_insufficient`，
   审计依据中同时记录所需级别与主体级别。
4. 以上全部通过才放行。

三类拒绝原因与未知主体 **互不相同**（见 `DenyReason` 常量），
对外错误也可通过 `errors.Is` 区分（`ErrUnknownSubject` / `ErrAccessDenied`），
不存在静默放行或统一归类。

每次判定都记录依据：策略版本、命中规则 ID 与描述、参与判定的规则列表、
所需/持有级别，写入审计并在日志中打印。

## 脱敏规则

字段带有敏感级别（`public=0 < internal=1 < confidential=2 < secret=3`）。
放行后按策略 `field_modes: {级别: {操作: 模式}}` 逐字段处理：

| 模式 | 行为 |
| --- | --- |
| `keep` | 原样返回（缺省值） |
| `mask` | 部分遮蔽，保留首尾可读（如 `13812345678 → 1****8`） |
| `tokenize` | 不可逆令牌：`tok_` + `HMAC-SHA256(secret, "v1"·字段名·规范值)` |
| `drop` | 整体剔除 |

此外，**字段级别高于主体 clearance 时无论策略如何配置都整体剔除**：
输出 map 中不存在该键，不会返回空值、零值或占位符。

一致性与安全性：

- 令牌化是无状态纯函数，并与**字段名**绑定（避免不同字段同值被关联推断）；
- 同一主体重复访问、多协程并发访问，输出逐字节一致（测试用 `-race` 校验）；
- 令牌不含明文片段，无密钥不可逆；进程/状态重载后只要密钥不变，令牌不变；
- 换密钥则令牌不同，密钥不参与任何返回值外泄。

## 策略版本与热更新兼容范围

- 策略以 `*Policy` 整体发布，发布后不可变；`Store` 用原子指针保存当前版本，
  判定开始时取一次快照，**进行中的判定永远基于同一个完整版本，读不到半更新状态**。
- 版本号采用 `major.minor.patch`（缺段补 0）。
- 加载新版本时按顺序校验，任一失败都返回错误且 **原策略继续可用，不部分生效**：
  1. 合法性：版本非空、至少一条规则、规则 ID 非空、枚举合法；
  2. 不允许版本回退（`next < current` 返回 `ErrIncompatiblePolicy`）；
  3. 兼容性下界：新版本声明的 `min_supported` 不得高于当前版本，
     即 `current >= next.min_supported` 才接受。
- JSON 文件中 `min_supported`、`field_modes`、`description` 等字段缺失
  视为旧版定义，按缺省容忍加载；非法枚举（未知 action / mode）明确报错。
- 判定结论中带有所用策略版本；保存旧策略快照即可在任意时刻用判定引擎
  **复现旧版本上的历史结论**，不受当前新版本影响（有对应单测）。

策略文件示例见 `gateway/testdata/policy-v2.json`：

```json
{
  "version": "2.0.0",
  "min_supported": "1.0.0",
  "rules": [
    {"id": "legal-read", "departments": ["legal"], "actions": ["read"], "min_level": 1}
  ],
  "field_modes": {"2": {"read": "tokenize"}}
}
```

## 本地验证

```bash
# 全部单元测试（含输入与判定依据日志）
go test -v ./...

# 竞态检测（覆盖重复/并发脱敏一致性、并发热更新不读半状态）
go test -race ./...

# 静态检查
go vet ./...

# 端到端演示：正常访问、三类拒绝、未知主体、热更新与兼容拒绝、审计打印
go run ./cmd/demo
```

测试覆盖场景：

- 越权（操作被拒 / 级别不足）、未知主体、策略缺失，拒绝原因两两可区分；
- 脱敏与令牌化在重复访问、50 协程并发访问、脱敏器状态重载下结果一致；
- 无权字段整体剔除（无键、无空值、无占位符）；两个入口输出一致；
- 并发热更新期间判定快照自洽；兼容版本接受、不兼容/降级/非法版本拒绝且原策略可用；
- 旧版本历史判定结论可复现；审计记录包含输入、判定依据、保留/剔除字段，
  测试日志中打印输入与依据（`go test -v` 可见）。
